# Fix: Teammate-to-Teammate Messaging

**Date:** 2026-08-16  
**Status:** Ready for implementation

---

## Problem Summary

The messaging system uses a single-owner model — every conversation/message is keyed to one `user_id` (creator). When teammate B tries to access a conversation created by teammate A, every access gate rejects with 404 even if B is listed in `member_ids`.

---

## Files to Change

| File | Lines | Change |
|---|---|---|
| `app/services/smartflow/_base.py` | 318–339 | Add `member_ids` access path to `_get_accessible_conversation` |

## Change Details

### 1. `_base.py` — `_get_accessible_conversation` (lines 318–339)

Add a third access path: if the user is in `member_ids` of any non-archived conversation (even if they're not the owner), allow access.

```python
async def _get_accessible_conversation(self, user_id: str, conversation_id: str, code: str = "CONVERSATION_NOT_FOUND") -> dict:
    if not ObjectId.is_valid(conversation_id):
        raise AppException(status_code=404, code=code, message="Requested resource was not found.")

    # Path 1: owner
    conversation = await self.db.conversations.find_one({"_id": ObjectId(conversation_id), "user_id": user_id})
    if conversation:
        return conversation

    # Path 2: global chat member
    conversation = await self.db.conversations.find_one({"_id": ObjectId(conversation_id), "is_global_chat": True})
    if conversation:
        if conversation.get("is_active", True) is False:
            raise AppException(status_code=404, code=code, message="Requested resource was not found.")
        user = await self._get_user_document(user_id)
        organization_id = user.get("organization_id")
        if (
            not organization_id
            or conversation.get("organization_id") != organization_id
            or user_id not in conversation.get("member_ids", [])
            or not self._user_has_global_chat_access(user)
        ):
            raise AppException(status_code=403, code="GLOBAL_CHAT_ACCESS_DENIED", message="You do not have access to this global chat.")
        return conversation

    # Path 3: non-global conversation member (teammate inbox)
    conversation = await self.db.conversations.find_one({"_id": ObjectId(conversation_id), "member_ids": user_id})
    if conversation:
        return conversation

    raise AppException(status_code=404, code=code, message="Requested resource was not found.")
```

**Why:** The original code fell through to 404 for non-owners of non-global conversations. Path 3 catches the case where B is listed in `member_ids` but didn't create the conversation.

### 2. `conversation_service.py` — `list_conversations` (line 109 and 196–197)

**Line 109** — expand the base filter to include conversations where user is a member:

```python
# BEFORE
filters: dict = {"user_id": user_id}

# AFTER
filters: dict = {"$or": [{"user_id": user_id}, {"member_ids": user_id}]}
```

**Lines 196–197** — fix `participant_ids` typo (field never written to DB):

```python
# BEFORE
archived_count = await self.db.conversations.count_documents({"$or": [{"user_id": user_id}, {"participant_ids": user_id}], "archived": True})
active_count  = await self.db.conversations.count_documents({"$or": [{"user_id": user_id}, {"participant_ids": user_id}], "archived": {"$ne": True}})

# AFTER
archived_count = await self.db.conversations.count_documents({"$or": [{"user_id": user_id}, {"member_ids": user_id}], "archived": True})
active_count  = await self.db.conversations.count_documents({"$or": [{"user_id": user_id}, {"member_ids": user_id}], "archived": {"$ne": True}})
```

### 3. `conversation_service.py` — `list_messages` (lines 263–265)

When a non-owner member queries messages, filter by the conversation owner's `user_id` (not the requester's), so all messages in the conversation are visible.

```python
# BEFORE
filters: dict = {"conversation_id": conversation_id}
if not conversation.get("is_global_chat"):
    filters["user_id"] = user_id

# AFTER
filters: dict = {"conversation_id": conversation_id}
is_owner = conversation.get("user_id") == user_id
if not conversation.get("is_global_chat") and is_owner:
    filters["user_id"] = user_id
# If member but not owner: no user_id filter — fetch all messages in the conversation
```

### 4. `conversation_service.py` — `create_message` document (lines 286–287)

Always populate `sender_user_id` on new messages (not just global chat), so the actual sender is always traceable regardless of message ownership.

```python
# BEFORE
"user_id": user_id,
"sender_user_id": user_id if conversation.get("is_global_chat") else None,

# AFTER
"user_id": conversation.get("user_id", user_id),   # conversation owner's id for scoping
"sender_user_id": user_id,                          # always the actual sender
```

**Why:** Messages need to stay discoverable by the owner's `user_id` for existing queries. The `sender_user_id` field identifies who actually sent the message (important for UI "sent by" display and read receipts).

### 5. `conversation_service.py` — `delete_conversation` ownership guard (lines 226–232)

After access check, assert requester is the owner before deleting.

```python
async def delete_conversation(self, user_id: str, conversation_id: str) -> bool:
    conversation = await self._get_accessible_conversation(user_id, conversation_id, "CONVERSATION_NOT_FOUND")
    if conversation.get("is_global_chat"):
        raise AppException(status_code=400, code="GLOBAL_CHAT_DELETE_UNSUPPORTED", message="Global chat cannot be deleted.")
    # NEW: only the owner can delete
    if conversation.get("user_id") != user_id:
        raise AppException(status_code=403, code="CONVERSATION_DELETE_FORBIDDEN", message="Only the conversation owner can delete this conversation.")
    await self.db.conversations.delete_one({"_id": conversation["_id"]})
    await self.db.messages.delete_many({"conversation_id": conversation_id})
    return True
```

### 6. `conversation_service.py` — `archive_conversation` ownership guard (lines 215–224)

Same pattern — only the owner can archive.

```python
async def archive_conversation(self, user_id: str, conversation_id: str, archived: bool) -> dict:
    conversation = await self._get_accessible_conversation(user_id, conversation_id, "CONVERSATION_NOT_FOUND")
    if conversation.get("is_global_chat"):
        raise AppException(status_code=400, code="GLOBAL_CHAT_ARCHIVE_UNSUPPORTED", message="Global chat cannot be archived individually.")
    # NEW: only the owner can archive
    if conversation.get("user_id") != user_id:
        raise AppException(status_code=403, code="CONVERSATION_ARCHIVE_FORBIDDEN", message="Only the conversation owner can archive this conversation.")
    updated = await self.db.conversations.find_one_and_update(
        {"_id": conversation["_id"]},
        {"$set": {"archived": archived, "updated_at": utc_now()}},
        return_document=ReturnDocument.AFTER,
    )
    return await self._serialize_conversation(updated, viewer_user_id=user_id)
```

## What Does NOT Change

- `require_permission("messages", "view/send/delete")` — unchanged, still enforced at FastAPI layer
- Global chat logic — untouched, its own path
- `_get_accessible_message` — already delegates to `_get_accessible_conversation`, so it inherits the fix for free
- WebSocket stream handler — inherits the fix via `get_conversation()` call, no separate change needed

---

## Risks / Notes

- **Existing data:** Conversations created before this fix may have empty `member_ids`. Those will still only be accessible by their owner until `member_ids` is backfilled during conversation creation.
- **`mark_conversation_read` for non-owner members:** Currently uses `user_id` filter on messages (`line 244`). After the fix, non-owner members can call this endpoint. The filter `{"user_id": user_id, ...}` will match zero messages for non-owners (messages belong to owner's `user_id`). This needs a companion fix matching the `list_messages` pattern — but it's lower priority and not part of this patch.
- **`read_by` array** on messages already works for global chat. For non-global-chat messages created after this fix, `read_by` is initialized to `[]`. Read receipts for non-global conversations still use the `status`/`unread_count` fields — this is unchanged.
